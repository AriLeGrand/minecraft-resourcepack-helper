## 1. What we are building

A standalone desktop app (Tauri 2 + Rust core + TypeScript/React UI) that
replaces my Aseprite plugin for making Minecraft Java resource packs. It has
its own Aseprite-style pixel editor, a texture browser, animation tools, 3D /
particle / GUI previews and version-aware export.

Sources of truth (read them completely before doing anything else):
- `docs/superpowers/specs/2026-11-19-pack-creator-design.md`: the approved design.
  Follow it. If you must deviate, write down why in `docs/DECISIONS.md`.
- `docs/mockups/*.dc.html` and their `README.md`: the screens to reproduce
  (layout, colours, labels, behaviour). They are not runnable; read the markup.
- `main.lua` and `modules/*.lua`: the old plugin, reference only for
  `.minecraft` detection, version and folder logic. Do not modify or delete
  them. Do not port the "save on switch" bug described in the design.

## 2. Ground rules

- Git: work on the branch `claude/wizardly-gauss-5killp`. Commit after every
  working step with a clear message, and push at the end of each stage. Never
  force-push, never rewrite history, never commit secrets.

## 4. Stage 0: check the facts

Before writing app code, check the design's section 5 ("Domain facts") against
my real files. Read the files directly from the `.jar` with a small script, and
don't copy any textures into the repo. Check:
- the `version.json` `pack_version` field in each installed jar;
- the texture folder names in old vs new versions (`blocks` vs `block`, etc.);
- the GUI sprites folder and its `.mcmeta` scaling files (1.20.2+);
- the particle JSON files (1.14+) vs `particles.png` (older versions);
- example animated textures and their `.mcmeta`.

Write what you found in `docs/research/domain-facts.md`. Correct the design doc
where it's wrong and note each correction in `docs/DECISIONS.md`. Build the

installed versions to help), and the particle-sheet cell map for old versions.
Add tests for all of it.

## 5. Stages

For each stage: write a short plan in `docs/superpowers/plans/stage-N.md`
(steps, and how each is tested). Then build it, run all checks, run the app,
take screenshots, compare them to the mockups and fix differences, update
`PROGRESS.md`, commit, push, and give me a short summary with the screenshots.
Then continue with the next stage.

**Stage 1: foundation and texture browser** (screens 1, 2, 5)
- Tauri 2 app in `app/`, with the shell and visual system as reusable components.
- Settings and recent packs persisted in the app data folder.
- Detect `.minecraft`. Extract textures from the jar in Rust (zip crate, no
  shell commands) into a cache per version. Read `pack_format` from the jar,
  with the fallback table.
- Create or open a pack, with `pack.mcmeta` and a placeholder `pack.png`.
- Texture index across all categories, with thumbnails generated and cached in
  Rust. The list must stay smooth with 3000+ textures (virtualised).
- Texture browser as in the mockup:
  - search across all categories, categories with counts, status filters;
  - an inspector comparing vanilla and my version, with "name across versions";
  - Import image (pixel-exact; a tall image is offered as animation frames);
  - Open externally (my configured editor, e.g. Aseprite, or the system
    default), with file watching that refreshes previews.
- Pack and export screen: icon, description with `§` colour preview, checks with
  fixes, export as folder or `.zip`, install into `resourcepacks`, extra copies
  for older versions using the rename table.
- Build a Windows installer with `tauri build` at the end of the stage.

**Stage 2: pixel editor** (screen 3)
- Canvas with pixel grid, zoom and pan.
- Tools: rectangle select, lasso, magic wand, move, pencil, spray, eraser,
  eyedropper, bucket, gradient, line, curve, rectangle, ellipse,
  contour/polygon, shading ink, blur/jumble, text, hand, zoom.
- Tool options: size, ink, opacity, pixel-perfect, symmetry, tiled mode, onion
  skin. Aseprite-like keyboard shortcuts.
- Layers (visibility, lock, opacity, order), a locked semi-transparent vanilla
  reference layer, and a palette with "from vanilla".
- Colour picker with foreground/background colours, undo/redo as a command
  stack, copy/paste, open-file tabs with unsaved markers.
- Preview panel: Tiled and Original tabs (3D comes in stage 4).
- Working files go in `.packcreator/` inside the pack. Export writes flat PNGs.
- Add tests for the tools' pixel logic (Vitest or Rust).

**Stage 3: animation** (screen 4)
- Timeline with frames and per-frame duration, onion skin, playback at in-game
  speed (1 tick = 50 ms), loop.
- Import a vertical strip as frames, and export as a vertical strip plus `.mcmeta`
  (frametime, interpolate, frame order).
- Show the generated file, and check that `.mcmeta` files round-trip.

**Stage 4: game previews** (Editor and Animation preview tabs, screen 7)
- 3D block preview with three.js: full cubes first, then shapes from the block
  model JSON in the extracted jar (stairs, slabs, fences…). Rotate, light and
  dark backgrounds, live update while drawing.
- Particle viewer: list, live scene (night, day, underwater; ¼×, 1×, 2× speed;
  your pack vs vanilla), particles only by default. Both layouts: shared
  `particles.png` with the selected particle's cells highlighted and editable
  alone (warn about shared cells), and 1.14+ separate images with
  `particles/<name>.json`. Show the note that movement is approximate.

**Stage 5: interface editor** (screen 6)
- Screens list, the pieces on each screen with their status, an assembled
  in-game preview at GUI scale 1×/2×/3×, click a piece to select it.
- Stretch / Tile / Nine-slice with borders and a preview at 3 widths, plus the
  generated `.mcmeta`. A fallback for pre-1.20.2 single GUI images.

**Final**
- Full test pass and a release installer.
- Rewrite `README.md` for the new app: install, quick start, screenshots.
- A list of known limitations and ideas for "later" (Blockbench link, models).

## 6. Quality bar (every stage)

- `cargo test`, `cargo clippy -D warnings`, `cargo fmt --check`, front-end
  typecheck, lint and tests must all pass before a commit that ends a step.
- Run the app for real and look at it (screenshots). "It compiles" is not done.
- No success popups: use the status bar or toasts. Errors must be clear and say
  what to do.
- Handle these cases: no Minecraft installed, a version never launched (no
  jar), a corrupted jar, read-only folders, very large packs.
